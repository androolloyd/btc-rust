# Repository review — 2026-10-11

This is an experimental implementation. A green unit suite does not establish Bitcoin Core consensus parity or make every advertised node feature operational. Remaining implementation work is tracked in [BUILD_PLAN.md](BUILD_PLAN.md).

## Fixed findings

- **P1 — finalized PSBT spends had no offline verification path:** extraction previously copied final bytes without evaluating spending conditions. The separate `verify-psbt` command now uses real ECDSA/Schnorr equations, all prevouts and the existing script engine for known key/multisig templates, with explicit unsupported errors for future/arbitrary scripts. It rejects missing context, unsafe witness-only legacy amounts, altered final signatures/declared types, noncanonical encodings/wrapped pushes, duplicate/null inputs and invalid value totals. The result names its supplied-prevout scope and keeps unused partial-record and active-chain verification false. Core v29 independently accepts nine spend types, 26 hash-mode variants and a two-input Taproot case; signature corruption fails both implementations, and cross-input prevout substitution fails the first Taproot equation. Ordinary consensus is unchanged; generalized wallet signing and chain admission remain open.

- **P1 — unchecked PSBT signature encodings and sighash contradictions:** ECDSA partial records formerly accepted arbitrary bytes; Taproot records only checked 64/65-byte length. The tools now require canonical DER/nonzero in-range ECDSA scalars, BIP340 numeric bounds, defined sighash encodings and agreement with declared types. Explicit Taproot DEFAULT and unsupported/draft types fail; known spending programs constrain signature kind/default use and Taproot SINGLE requires a corresponding output. V2 signing permissions and SINGLE pairing flags follow known partial signatures, including conversion. Complementary combine results fail atomically on contradictions. High S is preserved as metadata; parsing does not verify signature equations or opaque final script/witness records. The separate final-spend verifier applies low-S and evaluates supported templates. Independent Core/BIP340 encoding vectors and real Core-signed sighash variants exercise the compiled paths.

- **P1 — PSBT key records accepted non-curve and inconsistent extended keys:** legacy partial-signature/input/output-origin keys previously only needed a prefix and byte count, while global xpubs only needed 78 bytes. All now require real secp256k1 keys. Global standard xpub/tpub headers enforce BIP32 master metadata and bind origin depth, terminal child index and directly known master fingerprints. Public models use the same checks before extraction or atomic combining. BIP32 private/public decoders also reject nonzero master parent/index metadata. CLI inspection now exposes legacy origins and actual global xpub records. Acceptance uses all 17 valid BIP32 key pairs, all 16 invalid extended keys, 27 independently wrapped/published PSBT cases and Core-signed spends. Full origin proofs and partial-signature equations remain unfinished; DER/sighash metadata and supported final-spend verification are implemented in subsequent milestones. Core's PSBT decoder preserves custom version bytes and does not validate all origin claims; this implementation explicitly limits global versions to standard xpub/tpub and reports those stricter checks separately.

- **Tooling — Core relay acceptance depended on a randomized privacy timer:** exact-head CI for `2aec151` passed the push run but timed out in the duplicate outbound-v2 Core-to-Rust mempool wait. Core v29 inventory scheduling uses exponential delays with no fixed upper bound; the old 30-second wait did not drive that scheduler. The regtest fixture now freezes Core's mockable clock, proves a real transaction stays unannounced while time is frozen, and advances the actual scheduler during relay waits under bounded wall-clock/time limits. No whitelist permissions or validation exemptions are granted. Failure diagnostics now include pools/tips, live peer message counters and transport/admission logs. The historical failed run lacked packet diagnostics, so its precise cause remains unproven; this repair removes the known timer dependency and makes a recurrence diagnosable. Production relay and consensus code are unchanged.

- **P1 — unchecked PSBT Taproot commitments:** curve-valid internal keys, leaf/control records and output trees previously passed without proving their relationship to the claimed outputs. BIP341 tagged hashing, actual curve tweaking and output parity now bind supplied control proofs to available P2TR prevouts; explicit internal-key/root pairs and complete output-tree/internal-key pairs are checked as well. Leaf proofs must agree with each other and optional internal/root fields. Known non-Taproot outputs reject Taproot records. All seven published wallet commitment cases and twelve control proofs cover exact tweaks, roots, leaf hashes and output keys, including a future even leaf version. Invalid public models and conflicting combines fail before extraction or mutation. Absent roots/trees can mean unrevealed scripts, so dependent checks remain incomplete; no signature or active-chain claim is made. Existing consensus commitment hashes now share the primitives implementation with identical rules.

- **P1 — PSBT spending-data substitution:** full parent transactions previously were not linked to input txids/indices; conflicting witness records and supplied redeem/witness scripts could pass the wallet tools. Full parents now require matching txids and existing output indices, dual UTXO records must match amounts/scripts, and known P2SH/P2WSH commitments are checked for inputs and outputs. Public-model and combine validation use the same checks, preventing extraction or partial mutation on contradictions. CLI inspection exposes resolved prevouts and distinguishes txid-linked parents from witness-only updater claims. Acceptance includes eight published BIP174 valid-format examples, three published signer-script failures, wire/model and atomic-merge regressions, and Core-generated legacy/native/wrapped witness spends with actual script commitments. No confirmation, unspentness, signature verification or wallet signing is implied.

- **P1 — malformed Taproot PSBT records escaped validation:** BIP371 leaf-script, Taproot origin and output-tree types formerly passed through as unknown records. They now have typed parsing, serialization, conversion, combining and compiled CLI inspection. X-only keys are checked on secp256k1; control-block size/depth and leaf-version agreement, canonical bounded hash counts and complete key origins, and complete depth-first output-tree topology are checked. All 17 published BIP371 vectors are retained with source provenance; malformed records and invalid models fail without partial merge mutation. The Core wallet acceptance script now requires a real script-path spend with a NUMS internal key, checks leaf/control/origin/tree metadata, and compares all published cases against Core. Parsing still does not prove signature equations, derivation claims, active-chain UTXO status or script satisfaction; commitment checks requiring absent data remain deferred.

- **Tooling — nondeterministic BIP39 rejection test:** an Ubuntu CI run exposed a test that randomly changed the final mnemonic word and assumed its checksum must fail. That word also contains entropy; the replacement can be another valid mnemonic. Rejection now flips each checksum bit without changing entropy, deterministically across all five word counts and three entropy patterns. A fixed valid-replacement pair proves the former assumption false. All 24 English reference vectors linked from BIP39 now check complete phrases, restored entropy, exact 64-byte seeds and BIP32 master extended private keys. No production checksum rule is relaxed.

- **P1 — false PSBT v2 support and unsafe wallet parsing:** the former parser always required a global unsigned transaction and its serializer emitted that field even for v2. BIP370 now reconstructs the actual transaction from required v2 map fields, excludes v0/v2-incompatible fields and resolves input locktime requirements. Canonical CompactSize key types, raw-key uniqueness, singleton/fixed lengths and full consumption are checked. Lengths/counts are bounded before allocation; corrupted model counts cannot panic extraction. Combining validates an isolated result before mutation and uses linear key unions. Compiled CLI inspection/conversion/extraction has all published BIP370 cases plus real Core v29 signed/finalized SegWit/Taproot acceptance. These tools do not claim to verify signatures or sign wallet transactions; complete BIP174/371 semantics remain tracked.

- **P0 — Taproot signature bypass:** the generic witness dispatcher returned success for any nonempty Taproot witness. It now runs the real key/script-path verifier. Parallel block verification supplies every prevout required by BIP341; the regression proves a valid two-input signature fails when another prevout amount changes.
- **P0 — double spending:** block connection reused entries from the immutable external UTXO view. It now tracks all spent outpoints, rejecting duplicate inputs and cross-transaction double spends.
- **P0 — UTXO resurrection:** cached deletions fell through to the database before a flush. Tombstones now hide those entries immediately. Outputs created and spent within a block are omitted from forward state and undo restoration.
- **P0 — fabricated RPC success:** submitblock previously accepted structure without executing scripts or changing the chain; regtest mining returned invented hashes. RPC and sync now use one validated backend. It commits actual blocks/headers/transactions/coins/tip atomically, rejects failed validation, mines real regtest blocks and restores the committed chain on restart. Missing data or a missing backend produces an error.
- **P1 — header fork index corruption:** accepting a heavier fork changed the tip without replacing earlier height mappings. The index now follows every affected fork ancestor; a regression verifies lookups on the new branch.
- **P1 — consensus construction mismatch:** BIP34 encoding now uses Core's OP_1..OP_16 for small heights, all miner/test harness coinbases share that encoding, and contextual reward validation uses each network's halving interval. Updated regtest activation heights to Core v29 defaults.
- **P1 — RPC transport failure/shutdown:** bind failures are returned to startup, request buffering is bounded, stop wakes the listener and returns its response, and node startup runs sync in the background so RPC stop can terminate the node.
- **P1 — missing inbound transport/runtime:** the configured P2P port previously had no listener. Startup now binds a bounded listener, detects BIP324's v1 prefix without discarding bytes, responds at the first mismatching byte for v2, authenticates transport packets, and exchanges the real version handshake. It serves committed headers/blocks and validates requested bodies through the shared backend; post-commit notifications drive block relay. Peer queries use live addresses and transport/session data. Core v29 interoperability passes on both transports, including matching v2 session IDs and independently validated blocks both ways.
- **P0 — persistent forks/reorgs were unsupported:** the shared backend now validates fork-specific coins and ancestor MTP, stores side bodies/undo durably, retains equal-work ties and atomically replaces coins, active indices, pool and tip on greater accumulated work. Versioned undo records bind to the block hash and verify a checksum. Body/history databases can backfill undo only through replay matching their committed coins. Invalid winning bodies, corrupt undo and injected commit failure cannot publish replacement state; restart restores both active and side branches.
- **P1 — missing runtime mempool:** RPC/P2P admission now verifies real prevouts and signatures, range/conservation, maturity, finality, relative locks, fees and dependency limits. Pool transactions persist and are revalidated on restart and every active-tip change; disconnected transactions are reaccepted when valid, and conflicting parents/descendants disappear. Txid/wtxid negotiation drives real relay and bounded orphan-parent requests. Mining includes actual pool transactions, fees and witness commitments; full/opt-in RBF, CLI policy settings and RPC max-feerate/burn limits are enforced. Core v29 accepts signed transactions and replacements from this node and validates its mined witness blocks and spend reorgs.
- **P1 — missing RPC-origin notifications:** commit/revert/reorg events now originate in the shared backend after durable commit, including RPC and both P2P directions. No post-commit undo read can turn an already committed block into a reported rejection.
- **Tooling — QMDB thread exhaustion:** CI exposed the upstream 512-thread per-database prefetch default. The adapter caps it to available CPU capacity, at most eight workers, and the complete local suite passes.
- **P1 — outbound relay did not process blocks:** after IBD the outbound loop previously only logged announcements. It now shares the inbound bounded request/validation/committed-data path, serves actual blocks and emits real outbound ExEx commits. Explicit peers disable DNS discovery; disconnects retry with bounded backoff and reload the durable tip, including intervening RPC commits. Tip-only announcements request connecting headers, preventing a missing-parent body from being mistaken for a fork. Released Core v29 passes initial sync, live relay both ways, forced reconnect and database restart on v1/v2.
- **P1 — concurrent block delivery:** a requested body may already have been committed by RPC or another peer. In-flight and queued duplicates are now discarded without treating them as forks or disconnecting an otherwise valid peer. A regression exercises that race and confirms invalid rewards still fail without publication.
- **P1 — unsafe cache references:** read-through insertion could rehash a HashMap while earlier entry references remained live. The consensus UTXO API now returns owned entries; the persistent cache uses a mutex and bounded clean reads.
- **P1 — lost dirty outputs:** cache eviction discarded creations before persistence. Dirty entries remain pinned until a successful transaction commits. Failed writes retain the pending delta.
- **P1 — BIP141 commitments:** validation skipped coinbase-only witness, ignored commitments in otherwise legacy blocks, and substituted a zero nonce for malformed witness. It now checks any present commitment, requires one 32-byte reserved value, and rejects witness without a commitment. Mining templates generate the actual commitment.
- **P1 — checkpoint and delivery ordering:** validated tips commit with their UTXO delta, JSON checkpoints follow successful persistence, and restart checks the committed tip against the header chain. Reversed peer blocks are buffered and validated in height order; unrequested blocks cannot reduce the requested count. A local P2P regression covers both cases.
- **P1 — missing contextual checks:** sync now calls contextual UTXO validation and witness/Signet checks, without retrying consensus failures against a different UTXO view. BIP68 time locks and BIP113 finality receive ancestor median-time-past; script flags follow historical activation heights.
- **P1 — fake BIP324 cryptography:** replaced public-key hashing, publicly computable pseudo-ECDH, and pseudo-HKDF with libsecp256k1 ElligatorSwift XDH and HMAC-SHA256 HKDF. Packet length encryption, separate transport/application headers, command IDs, authenticated garbage, version exchange, and 224-packet rekeying match official vectors. The sync client negotiates encrypted transport and can reconnect using v1.
- **P1 — fake BIP352 cryptography and wrong addresses:** addresses now use a separate 5-bit version, validate curve keys, and encode the 66-byte key payload. Sender and receiver implement eligible input extraction, scalar/point aggregation, Taproot parity normalization, smallest serialized outpoint, actual ECDH points, labeled outputs, and grouped counters. All 28 official send/receive cases are checked.
- **P1 — fake Signet validation:** solution parsing now reads optional data from the selected coinbase commitment, constructs the two BIP325 virtual transactions, and executes the actual challenge. Corrected the default operator key; its derived network magic matches Core.
- **P1 — BIP39 Unicode seed mismatch:** passphrases and mnemonic text are normalized with NFKD before PBKDF2.
- **P1 — permissive decoding:** full-buffer decoding rejects trailing bytes, CompactSize rejects nonminimal forms, and transactions reject a superfluous witness record. Stream decoding remains composable. Two preexisting transaction fixtures contained an extra byte and were corrected.
- **P1 — remotely triggered reject parser panic:** CI fuzzing found that a reject string declaring `u64::MAX` bytes caused a capacity-overflow panic. Both string lengths are now checked against the remaining payload before allocation; direct and correctly checksummed framed regressions cover oversized and truncated lengths.
- **P1 — monetary arithmetic:** block connection rejects invalid values and checked totals beyond MAX_MONEY rather than risking signed overflow or negative-output inflation.
- **Tooling:** fixed the all-feature FFI build, marked raw-pointer exports unsafe for Rust callers, routed legacy FFI through the input verifier, fixed fatal Clippy diagnostics, corrected the CLI RPC client, pinned Rust 1.88, included lockfiles, made the normal root build include btc-node, fixed the container build, and added CI and fuzz workflows.
- **Dependencies:** updated crossbeam-epoch, anyhow, and both rand release lines to patched compatible versions. QMDB still uses unmaintained bincode 1.3; replacing that serialization is a separate migration.

## Verification scope

The full workspace suite, official crypto vectors, feature-minimal checks, Clippy, formatting, native release build, container build, and bounded parser fuzz run are the intended completion checks. The detailed current results are recorded in BUILD_PLAN.md. External Core-to-node network interoperability, full-chain replay, restart/reorg behavior, and every placeholder backend are separate acceptance surfaces.

## API changes

`UtxoSet::get_utxo` returns an owned `UtxoEntry`. Silent payment APIs now require real input key/prevout information and return validation errors; the former pseudo-key API cannot produce interoperable payments. V2 decryption accepts complete packets including their encrypted length. Rust callers of raw-pointer FFI exports must use unsafe with valid buffers; the C ABI is unchanged.

RPC chain operations require the installed node backend. The transport is still newline-delimited JSON on local TCP; full Bitcoin Core HTTP compatibility and remaining mempool/Electrum integrations are unfinished. Persistent block-body methods are implemented for redb; other backends return an explicit unsupported error. Old tip-only databases without header history fail startup with a migration/resync error and are preserved. Persistent reorgs now use accumulated work and durable undo with atomic coin/index/pool/tip switching.

The inbound P2P listener supports v1/BIP324 and committed-chain block relay with bounded handshakes and buffering. It enables transaction relay through the validated mempool and records BIP339 txid/wtxid negotiation. Outbound steady-state integration, explicit peer connections and reconnect from the durable tip are now implemented. Persistent branch/reorg handling and bounded transaction relay are implemented. Package admission, dynamic fee estimation/eviction and fee-optimized package mining remain unfinished; complete Core consensus and policy parity is still unverified. BIP324 authenticates packets with the negotiated keys; it does not authenticate the peer's identity. The released-Core tests cover small regtest chains and are not a full-chain replay claim.

PSBT exposes optional BIP370 construction fields and a checked `try_serialize` API; invalid public models return errors there. The existing `serialize` convenience method panics on invalid models. CLI tools use hex explicitly. Decode/convert/extract report `signatures_verified: false`; the separate `verify-psbt` command reports true only after actual final-spend equations succeed for every supported input, and always reports active-chain and unused partial-record verification false. The legacy `finalize` method extracts externally finalized fields without verifying their spending conditions. Known UTXO and P2SH/P2WSH metadata contradictions now fail all tools, serialization and combining. `input_utxo` resolves supplied records with full-parent txid linkage, while CLI `txid_linked` explicitly does not establish active-chain status. Known Taproot proofs and output-tree commitments are now checked against available P2TR keys; absent roots/trees/keys defer dependent checks. See [PSBT.md](PSBT.md) for the verified scope and remaining wallet work.
