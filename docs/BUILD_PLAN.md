## Verification commands

`./scripts/check.sh` is the standard local gate. `cargo audit --deny unsound` checks dependencies. Run bounded fuzz smoke tests with `cargo +nightly fuzz run <target> -- -max_total_time=30 -rss_limit_mb=2048`. Verify external behavior against Bitcoin Core in regtest; do not use real funds for acceptance tests.

`python3 scripts/check_core_p2p.py --bitcoind /path/to/verified/bitcoind` runs disposable Core v29 regtest peers against the built node on loopback. It checks inbound and outbound v1/v2 negotiation, matching v2 session IDs, the transaction-relay flag and txid/wtxid negotiation, independently validated blocks in both directions, identical stored block bytes and shutdown. Outbound cases also check initial sync of 19 Core blocks, recovery after a forced disconnect with 20 missing blocks, restart from the same database and further bidirectional relay. The expanded cases also generate 105 wallet blocks, compare Core-signed SegWit admission/fees/vsize and fee-cap rejection, relay valid replacements, mine witness commitments, split two branches with a spend in the losing branch, reconnect, verify restored coins and re-admission, re-mine and restart. CI fetches the pinned official release and verifies its SHA256 manifest before this test.

The Core P2P fixture freezes its regtest clock from startup and advances it one second per failed transaction-relay observation, retaining the 30-second wall-clock deadline and a one-hour total advancement cap. Core's exponentially distributed inventory timers otherwise can exceed any fixed acceptance deadline. Each scenario first requires a real transaction to remain absent while the clock is frozen, then requires actual P2P admission after clock advancement. Peers have no whitelist permissions; signature/policy and block validation remain enabled. Failed waits report transaction IDs, both pools/tips and live peer message counters, plus Core networking/mempool and Rust debug logs. This fixture tests relay behavior, not real-time privacy scheduling.
